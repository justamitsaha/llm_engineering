# 4. Start With the Simplest Possible Baseline

The first model is intentionally extremely simple:

## Random Pricer

The function:

* Takes a product/item as input.
* Completely ignores the product description.
* Returns a random number between **1 and 999**.

Conceptually:

**Product → Ignore product → Random price**

This is obviously not expected to perform well.

But that's not the point.

### Why start with it?

It provides an initial reference point.

The project can then ask:

> **Can every subsequent model beat this result?**

This creates a progression:

**Random → Simple ML → Better ML → Neural Network → Frontier LLM → Fine-Tuned Model**

---

# 5. The `evaluate()` Function

The project uses an `evaluate()` function to measure how well a pricing function performs.

The evaluation function:

1. Receives a price-prediction function.
2. Receives the test dataset.
3. Runs the prediction function against test items.
4. Compares predicted prices with actual prices.
5. Calculates error metrics.
6. Visualizes the results.

By default, it evaluates the first **200 test items**.

The number can be changed if desired.

---

# 6. Parallel Processing

The evaluation can run multiple workers in parallel.

The default is:

**5 workers**

This means multiple evaluations can run simultaneously.

If the computer is being overloaded, the number can be reduced:

* `workers = 1`
* `workers = 2`

Similarly, the test size can be reduced, for example:

* `size = 100`

This makes experimentation faster and less demanding.

# 7. The Main Evaluation Visualization

One of the most important charts in the project is a **predicted-vs-actual scatter plot**.

It compares:

* **X-axis:** Actual price
* **Y-axis:** Predicted price

The terminology is:

* **y** = actual/true price, also called the **ground truth**
* **ŷ (y-hat)** = model's predicted price

Each dot represents one test item.

---

# 8. The Line of Perfection

The chart contains a dashed diagonal line representing **perfect predictions**.

If:

**Predicted price = Actual price**

the point lies exactly on this line.

Therefore:

> **The closer a point is to the line, the better the prediction.**

### Example

Suppose:

* Actual price = $300
* Predicted price = $433

The point appears at approximately:

**(300, 433)**

because:

* X = 300
* Y = 433

The model is therefore $133 away from the actual price.

---

# 9. Color Coding

The visualization also categorizes prediction quality:

* **Green** → close to the perfect-prediction line
* **Yellow** → somewhat far away
* **Red** → very far away

For the random model, the points are scattered widely because the predictions are random.

# 10. Random Pricer Results

The random pricing model performs very poorly.

The experiment produces an average error of approximately:

### **$382.08**

This means that, on average, the random prediction is around **$382 away from the actual price**.

This becomes the first number to record and beat with increasingly sophisticated models.

The key baseline is therefore:

> **Random Pricer → Average error ≈ $382.08**

---

# 11. Mean Squared Error (MSE)

The evaluation also calculates **MSE — Mean Squared Error**.

Conceptually:

**Error = Predicted − Actual**

Then:

**Squared error = (Predicted − Actual)²**

MSE takes the average of these squared errors.

It is a standard data-science metric for regression problems.

---

# 12. R² — R-Squared

Another evaluation metric is **R² (R-squared)**.

It measures how well the model explains the variation/patterns in the data.

### Interpretation

| R²           | Meaning                                      |
| ------------ | -------------------------------------------- |
| **1 / 100%** | Perfectly explains the variation             |
| **0**        | No better than simply predicting the average |
| **Negative** | Worse than predicting the average            |

The random pricer produces a **strongly negative R²**, showing how poorly it performs.

---

# 13. Why Test More Than 200 Items?

Testing on only 200 examples introduces uncertainty.

You might ask:

> “What if these 200 items were unusually easy or difficult?”

A different set of 200 items might produce a different result.

Therefore, the project also examines how the average error changes as the number of test examples increases.

### Behavior

Initially:

**Average error → highly volatile**

As more examples are added:

**Average error → stabilizes**

This helps determine whether the measured performance is reliable.

---

# 14. Confidence Interval

The second visualization includes a **confidence interval**.

The confidence interval represents uncertainty around the estimated average error.

In this experiment, the transcript gives an approximate interpretation:

> At a 95% confidence level, the random-pricer error is around **$382 ± $37**.

The shaded region on the graph represents this uncertainty.

### Why it matters

It reminds us that:

**Measured performance is an estimate, not an absolute truth.**

The more data used for evaluation, the more stable the estimate tends to become.

---

# 15. Evaluation Philosophy

The project isn't only interested in producing a single error number.

It wants to understand:

* How accurate the model is
* How predictions compare with ground truth
* How stable the evaluation is
* How much uncertainty exists around the measured result

The key number remains:

### **Average price error**

But the confidence interval is also useful for understanding the reliability of that number.
